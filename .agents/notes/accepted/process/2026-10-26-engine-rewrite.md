# 四维引擎重新编写，原型只作为玩法参照

Status: accepted

## Problem

仓库的代理说明 AGENTS.md 和框架文档都要求从已归档的 three.js 原型移植四维算法，并拿原型在相同输入下的输出逐条比对；代理说明还把原型称为移植四维数学的参考实现。但原型代码只为快速验证想法而写，没有经过仔细设计：谜题条件是针对单个谜题的硬编码判断，四维球和放样体没有切片算法，啃食效果是用着色器丢弃像素做出来的。照它翻译，这些写法会被一起带进正式引擎。

## Proposal

- 引擎的四维数学按框架文档重新设计、重新编写，不翻译原型代码。
- 原型只用来参照玩法和手感：第 8、9 场目前只有它能玩，白模做出来以后可以拿来对比。尺寸、时长等数值以框架文档为准。
- 引擎数学测试的期望值来自几何本身，不来自任何一份代码：
  - 能手算出精确结果的情形，例如对齐坐标轴的盒子转 90° 后的切片，四维球的切片半径 √(R² − d²)；
  - 必须始终成立的性质，例如旋转矩阵保持正交，翻面两次回到原来的手性，切片一定落在物体内部；
  - 框架文档尺寸规范里由公式算出的数值。例如四维球半径 0.25 米、球心在 W = 0.21 时，截面Ⅰ（W = 0）和截面Ⅱ（W = 0.42）切出的球半径都应约为 0.136 米，放在完好的楼板上时悬空约 0.114 米；又如普通物件竖起后，原截面里只剩 1.2 厘米厚的薄片。
- 文档随之修改：代理说明把原型描述为玩法参照，删掉对照原型输出的要求；框架文档里要求与原型逐条比对的那条解耦规则改写；框架文档模块表的「原型对应文件」一列改成原型里的对应行为，或者删掉。

## Alternatives considered

**翻译原型代码，再用 Node 脚本从原型生成对照数据。** 原型代码没有经过仔细设计，不值得照搬；和原型一致只能说明照搬准确，原型自己的错误也会被一起带过来。

**从文档里去掉所有对原型的引用，归档只作为历史保留。** 这样会失去指向可玩行为的线索，做白模时不方便对照手感。

**另用一种语言（例如 Python）独立写一套实现来比对。** 要维护两套实现，而且两套可能出于同一个误解写错。

## Acceptance criteria

- 引擎的四维数学测试只用上面三类期望值，不读取任何由原型生成的数据。
- 代理说明和框架文档不再要求对照原型输出，原型被描述为玩法参照。

## Risks

- UV 映射、切片多边形的顶点顺序这类几何性质测不到的细节，出错时只能在试玩中发现。
