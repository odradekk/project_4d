# 啃食者的搭法

[契约入口](contract.md) · [实体数据](contract-data.md) · [场景标注](scene-authoring.md)

**节点。** 啃食者用 `Grazer3D` 摆在区域场景的 `Grazers` 下。节点的 XYZ 加 `W` 是身体原点，初始旋转和别的四维实体一样：给 `Rotation4`（16 个数，一次一列 XYZW），或者转节点，不能两个都给；都不给表示不转。节点只给出第一帧，之后的移动、转身、张嘴和啃食由时间轴按帧交给引擎。

**身体。** `Shape` 是闭嘴时的身体：一组元球（`MetaballShapeResource`，每个球有 ID、四维中心、半径、权重，再加一个阈值），球心在啃食者自己的坐标里。`OpenShape` 是嘴张到最大时的身体，球的 ID 和顺序必须与 `Shape` 相同，不填表示嘴不会张开。

- 载入时引擎会在初始姿态上试一次 `OpenShape`，数值不合法的错误报在 `OpenShape` 上；`Shape` 里的错误报在 `Shape.Balls[序号]` 的字段上。两个形体之间的混合只在用到那一帧时由引擎检查，线性插值不能保证“权重凑得够阈值”（取决于球是否相交），不通过时时间轴报错并停下。
- 小球（倒钩、触须）的曲面直径不小于约 0.35 m。元球切片的网格是 0.2 m，转身或沿 W 移动时更小的球会闪现；白模阶段可以接受。

**时间轴。** `GrazerTimeline`（`game/creatures/`）是 C# 数据，用 `region.Grazers.Play("id", timeline)` 播放。

- 关键帧：时间、四维位置、各平面的转角、张嘴（0 闭，1 最大）。至少两个，第一个在 0 s，各帧转的平面和顺序相同。关键帧之间线性插值；旋转矩阵由引擎的 `Rotation4.FromPlaneAngles` 按转角算，不插值矩阵。张嘴在 `Shape` 和 `OpenShape` 之间按球逐项插值，半径和权重始终为正。
- 咬：时间、要啃掉的楼房元素、要咬断的接缝。`Play` 先检查这些 ID 存在，不存在就抛出异常，什么也不开始。
- 要啃的楼房元素必须写在“咬”里，不能直接调 `ConsumeStructure`，否则引擎里没了，Godot 里节点还在，看得见也撞得到。
- 分段 `Play` 时，后一段的第一个关键帧要接上前一段的最后一个，因为 `Play` 会让啃食者立刻跳到新时间轴的第一个关键帧。
- 引擎拒绝一帧或一次咬时，报一次错并让这条时间轴停下，啃食者留在上一帧。

**镜片与音乐。** 啃食者的切片在主画面和镜片里都画，没有碰撞，在镜片里和别的贯穿物一样有发光轮廓。每帧只切玩家所在的截面和镜片看的截面。背景音乐和画面闪烁按它与玩家的四维距离（量到身体原点）变化，距离阈值在 `GrazerLayers` 里。

**测试区域。** `game/regions/grazer_test.tscn`：三个截面，啃食者从 W=11 的深处出发。`game/tests/grazer_demo.tscn`（调试启动 `--start=grazer-demo`）让它沿时间轴逼近，啃掉一扇门和一道缝，再转身朝玩家走来。

**序章的啃食者。** 第 9 场的啃食者在 `game/regions/room/grazer.tscn`，路线在 `game/flow/DeepGrazer.cs`：一条从 W=14 进来、咬断接缝和三处楼房元素的时间轴，之后是每段 3 秒、朝小满当时的位置走的短时间轴，每段从上一段的最后一帧开始，用 `timeline.At(timeline.Duration)` 取。数值和时刻见[家的区域](home-region.md)。
